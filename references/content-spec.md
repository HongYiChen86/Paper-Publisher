# 内容与素材规范

## 1. 输出目录

对每篇论文使用独立目录：

```text
<paper-stem>-xhs/
  paper_manifest.json
  paper.txt
  contact-sheet-01.png
  pages/page-001.png
  selection.md
  content.json
  post.md
  publish_package.json
  publish_state.json
  cards/01-cover.png ...
```

不要覆盖旧版本；需要大改时创建 `v2` 目录。

## 2. 图片模式

默认使用 `source_pages`：直接选择 `prepare_paper.py` 渲染的完整 PDF 页面，不裁剪、不叠字、不加边框、不重画。推荐顺序为首页、动机/直觉页、主模型页、主实验页、消融/结论页。原始纵横比保留；小红书页面当前不强制统一比例，仍需满足格式、文件大小与清晰度预检。

仅在用户明确要求设计卡片时使用 `cards` 模式：

1. 封面：论文题目的人话版本 + 领域/任务 + 一句价值主张。封面不堆作者列表。
2. 问题/动机：现有方法哪里卡住，本论文解决什么。最多 3 个要点。
3. 模型结构：优先裁剪作者的主方法图，配 2-3 个简短步骤；不要擅自重画导致语义变化。
4. 核心实验：一个主指标或最能说明结论的对比，注明数据集、指标、页码/图表号。
5. 结论/适用场景：贡献、限制、适合谁看，并标注论文出处。

四张版合并第 2 与第 5 张，保留模型图和实验图。

## 3. `content.json` 字段

```json
{
  "source": {
    "paper_pdf": "paper.pdf",
    "paper_title": "Paper title",
    "selection_file": "selection.md"
  },
  "post": {
    "title": "最终标题",
    "body": "完整正文",
    "topics": ["论文速读", "计算机视觉"]
  },
  "publish": {
    "mode": "draft",
    "scheduled_at": null,
    "timezone": "Asia/Shanghai",
    "visibility": "public",
    "collection": {
      "enabled": true,
      "name": "论文分享"
    },
    "originality": {
      "enabled": false,
      "requested_default": true,
      "rights_confirmed": false,
      "basis": "paper commentary with cited figures"
    }
  },
  "style": {
    "author_tag": "PAPER NOTE",
    "background": "#FFF8F4",
    "foreground": "#241F20",
    "accent": "#FF2442",
    "muted": "#736A6C"
  },
  "cards": [
    {
      "kind": "cover",
      "kicker": "PAPER QUICK READ",
      "title": "卡片主标题",
      "subtitle": "一句补充",
      "bullets": ["短要点"],
      "source_image": "pages/page-001.png",
      "crop": [0.05, 0.08, 0.95, 0.48],
      "source_page": 1,
      "source_label": "论文首页"
    }
  ]

```

`source_pages` 模式不用 `cards` 字段，改为：

```json
"source_pages": [
  {"order": 1, "path": "../pages/page-001.png", "source_page": 1},
  {"order": 2, "path": "../pages/page-003.png", "source_page": 3}
]
```

## 4. 固定小红书文案结构

参考用户提供的发布表单布局，但每篇论文重新填充事实，不复制示例的具体内容：

标题采用小红书钩子形式，但不能为了吸引力牺牲准确性：

```text
{emoji}{会议/年份}｜{论文核心问题、反差发现或一句结论}
```

正文默认使用下面的 emoji 分段模板。保留与当前论文有证据对应的段落；没有证据的段落删除，不能硬填：

```text
📌 论文名称：

{英文全名}

🧠 一句话介绍论文

这篇工作提出：

{任务背景和核心主张，1-2 个短段落}

作者发现：

🔥 {有证据的观察 1} 🔥 {有证据的观察 2} 🔥 {有证据的观察 3}

更关键的是：

✅ {模块/贡献 1}

✅ {模块/贡献 2}

🧩 核心思路

{解释方法如何工作；必要时用“📌 名称：结论 / 说明：解释”结构}

📊 实验结果

📌 {数据集、shot、指标、数值}

📌 {第二个可核对结果或消融边界}

🎯 适用方向

✅ {方向 1} ✅ {方向 2} ✅ {方向 3}

⭐ 推荐指数：{基于论文内容的平衡推荐语}{emoji}

⚠️ 阅读提示

{模型、数据、backbone、评测协议或独立复现边界}

📎 说明

本文为论文解读，图片为 PDF 原始论文页，数据来自作者报告，不代表独立复现。
```

- emoji 用来区分段落和强调已核对信息；不要连续堆叠到影响可读性，也不能把“可能、相关、作者报告”改成确定性结论。
- `topics` 与正文分开保存；本用户默认固定为 `大模型`、`Agent`、`深度学习`、`科研绘图`、`多模态人工智能`、`计算机视觉`。确认卡片中必须显示全部带 `#` 的关键词，浏览器阶段仍要通过平台候选提交真实话题实体。当前任务有明确修改时以用户最新列表为准。

- `crop` 是 `[左, 上, 右, 下]` 的 0-1 相对坐标；必须满足左 < 右、上 < 下。
- `source_image` 相对 `content.json` 所在目录解析，也可用绝对路径。
- 小红书发布标题按 20 个 Unicode 码点预检；卡片内部标题推荐 8-28 个汉字；卡片要点每条推荐不超过 34 个汉字。平台限制仍以发布页实时显示为准。
- `scheduled_at` 使用带时区的 ISO 8601，如 `2026-08-21T20:00:00+08:00`。没有用户时间时保持 `null`。
- `topics` 不带 `#`，浏览器阶段通过平台真实候选逐个提交。
- 默认合集为 `论文分享`；用户在当前任务明确指定其他合集时替换。确认卡和页面回读必须显示最终合集。
- 原创声明默认列为“计划开启”，但 `originality.enabled` 在权利确认前保持 `false`。只有用户明确确认当前论文原页和解读文案满足原创声明要求后，才能把 `enabled` 与 `rights_confirmed` 同时改为 `true`、刷新包指纹并重新确认。
- 本 Skill 固定生成 1242x1656、3:4 PNG；单图不得超过 32 MiB。平台页面规则如有变化，按 `continuous-improvement.md` 记录并回流。

## 5. 事实核对

- 数字：核对数值、单位、指标方向和实验设置。
- 图表：记录 Figure/Table 编号与 PDF 页码；论文印刷页码与 PDF 页码不一致时写清 PDF 页码。
- 对比：确认 baseline、shot 数、backbone、数据集和评价协议一致。
- 措辞：作者未做统计显著性检验时避免使用“显著提升”；未公开代码时不要写“可复现”。
- 引用：正文末尾写论文题目和作者/会议（能从论文确认时）；不要伪造 DOI、会议或开源地址。

## 6. 发布确认卡片

在浏览器上传前，把当前版本完整返回给用户，固定使用以下字段；正文不得只给摘要，必须展示将要填写到平台的全文：

```text
🏷️ 小红书发布确认卡｜等待确认

图片：PDF 第 {页码列表} 页（按上传顺序）
标题：{最终标题}
关键词：#{关键词1} #{关键词2} ...
内容（将完整填写到小红书）：
{平台正文全文}

加入合集：{论文分享/用户指定合集}
原创声明：{计划开启但等待权利确认/已开启及权利依据/关闭}
目标动作：{保存草稿/立即发布/定时发布（准确时间和时区）}
确认方式：回复“确认”→仅执行当前卡片所列的适配、上传、填写和保存草稿；回复“修改：...”→修改后重新预览。
最终公开发布：上传回读后另行回复“提交”，第一次“确认”不等于“提交”。
```

- 内容确认绑定当前包指纹；标题、正文、标签、图片或顺序变化后立即失效，必须重新展示并确认。
- 用户未明确确认时状态写为 `AWAITING_CONTENT_CONFIRMATION`，禁止上传和表单写入。
- 用户要求修改标题、内容、关键词、图片、合集、原创声明或目标动作时，旧确认立即失效；必须返回包含“标题 + 完整内容 + 全部 #关键词 + 合集 + 原创声明权利状态”的新卡片，并等待新的“确认”。
- 平台适配只能做不改变语义的机械处理；若可见内容有变化，回到本节重新确认。

## 7. 发布前检查

- 图片顺序与 `publish_package.json` 一致，且预检脚本返回 `ok: true`。
- 卡片上没有不可读的小字号表格；必要时裁剪并放大单个结果区域。
- 标题和正文没有“最强”“碾压”等无依据绝对化表达。
- 正文说明这是论文解读，而非本人复现结果（除非用户确有复现实验并提供证据）。
- 最终发布时间包含日期、时间和时区。
- `learning/incidents.jsonl` 中的已发生问题均已有当前任务处理结论；可复用修复已经过回归检查再晋升。
